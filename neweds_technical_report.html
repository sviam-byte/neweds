Загрузка, ориентация и atlas inventory

Применялось к нашим рядам сейчас: да, перед Stage 1.

Что помогает оценить: Проверяет, что матрицы правильно интерпретированы как time × ROI, а не перепутаны местами.

\[X\in\mathbb{R}^{T\times N},\quad T=600,\;N=167\;\text{до exclusion}\]

Полученные оценки

  • 39 субъектов: HC=15, SZ=24.
  • AAL3: 167 исходных ROI, 600 time points.
  • После decision layer: 159 primary ROI.

Интерпретация

Это базовый sanity check. Он защищает от грубой ошибки “считать время как ROI”, но не валидирует анатомическое наложение атласа.

Прокомментированный фрагмент алгоритма

# На входе может быть ROI × time или time × ROI.
# Для AAL3 ожидаем 167 ROI. Если одна из размерностей равна 167,
# по ней определяем, где ROI, а где время.
raw = read_csv(file_path)
n_rows, n_cols = raw.shape

if n_rows == expected_roi_count:        # пример: 167 × 600
    X = raw.T                           # приводим к 600 × 167 = time × ROI
    orientation = "ROI x time -> transposed"
elif n_cols == expected_roi_count:      # пример: 600 × 167
    X = raw                             # уже time × ROI
    orientation = "time x ROI"
else:
    status = "shape_error"             # нельзя молча считать метрики

Подводные камни

  • Не проверяет gray/white matter overlap.
  • Не проверяет within-ROI homogeneity.
  • Не объясняет системные zero ROI.

Zero/constant ROI QC

Применялось к нашим рядам сейчас: да, Stage 1 + Stage 1.5 decision.

Что помогает оценить: Находит ROI, у которых нет изменчивости во времени; они математически непригодны для большинства метрик.

\[\sigma_i^2=\frac1T\sum_t(x_{ti}-\bar x_i)^2\]
\[\text{constant if }\sigma_i<\varepsilon\]

Полученные оценки

  • ROI 35, 36, 81, 82 zero/constant у всех субъектов.
  • ROI 1 = Background исключён из conservative analysis.
  • SZ/1177_Ivanov_S_A имеет дополнительные zero/constant ROI 106 и 111.

Интерпретация

Это не маленький косметический дефект. Если у ROI нулевая дисперсия, корреляция делит на ноль, а Granger/MI/TE теряют смысл.

Прокомментированный фрагмент алгоритма

# Для каждого ROI-ряда считаем базовые QC-признаки.
x = X[:, roi]
finite = np.isfinite(x)

mean = np.nanmean(x)
std = np.nanstd(x)
zero_fraction = np.mean(x == 0)
missing_fraction = 1.0 - np.mean(finite)

# all-zero: вся область дала нулевой временной ряд.
all_zero_flag = np.all(np.abs(x[finite]) < eps)

# constant: дисперсия практически нулевая.
constant_flag = std < eps

# Почему это важно:
# если std=0, корреляция делит на ноль;
# MI/TE/Granger тоже становятся бессмысленными или нестабильными.

Подводные камни

  • Системные zero ROI надо не только исключать, но и объяснить upstream.
  • Нельзя заменять нулевой ряд синтетическим шумом.

Extreme amplitude / amplitude QC

Применялось к нашим рядам сейчас: да, Stage 1 + decision v2.

Что помогает оценить: оценивает, не выбивается ли ROI по масштабу сигнала относительно других ROI/субъектов. Это проверка именно масштаба/размаха ряда, а не “хорошести” связности.

\[A_i=\max_t x_i(t)-\min_t x_i(t)\]
\[z_i^{robust}=\left|\frac{A_i-\operatorname{median}(A)}{1.4826\cdot\operatorname{MAD}(A)}\right|\]

Если robust z-score амплитуды большой, ROI получает extreme_amplitude_flag. Дальше decision layer смотрит не на одну строку, а на частоту флага по субъектам.

Полученные оценки

  • Всего extreme_amplitude_flag=True строк: 107.
  • ROI 134: 100% субъектов.
  • ROI 133: 92.3% субъектов.
  • ROI 167: 43.6% субъектов.
  • ROI 160: 15.4% субъектов.
  • Decision v2: ROI 133/134/167 → sensitivity_only; ROI 160 → qc_flag_keep.

Интерпретация

Это помогает отделить стабильно подозрительные ROI от нормального primary set. Но extreme amplitude не доказывает артефакт. Это флаг на проверку extraction / scale / mask coverage / размера ROI и возможного отличия между группами. Поэтому 133/134/167 не удалены “навсегда”, а вынесены в sensitivity-only.

Прокомментированный фрагмент кода

# Вход: таблица subject × ROI, где для каждой строки уже посчитаны
# базовые признаки ряда: min, max, std, variance и т.д.
# Здесь extreme amplitude считается НЕ по абсолютному порогу,
# а относительно распределения амплитуд в этом же atlas/QC-run.

# 1) Амплитуда одного ROI-ряда:
#    это размах сигнала внутри ряда.
x = X[:, roi]                         # один ROI time series, например 600 точек
finite = x[np.isfinite(x)]             # убираем NaN/Inf, если они есть
amplitude = finite.max() - finite.min() # A_i = max_t x(t) - min_t x(t)

# 2) Собираем амплитуды всех subject × ROI строк того же атласа.
amp = qc_table.loc[qc_table["atlas"] == atlas, "amplitude"].to_numpy(float)

# 3) Считаем robust z-score через медиану и MAD.
#    Это лучше обычного z-score, потому что несколько огромных ROI
#    не сдвигают медиану так сильно, как сдвинули бы среднее.
median_amp = np.nanmedian(amp)
mad_amp = np.nanmedian(np.abs(amp - median_amp)) + 1e-12
robust_sigma = 1.4826 * mad_amp
robust_z = np.abs((amp - median_amp) / robust_sigma)

# 4) Ставим флаг, если ROI слишком далеко от типичного масштаба.
#    Порог 5 robust-sigma — консервативный: ловим не все отличия,
#    а только явно выбивающиеся амплитуды.
extreme_amplitude_flag = robust_z > 5.0

# 5) На decision layer агрегируем флаг по ROI:
#    считаем, у какой доли субъектов эта ROI получила extreme flag.
extreme_amplitude_frequency = (
    qc_table.groupby(["atlas", "roi_index_1based"])["extreme_amplitude_flag"]
    .mean()
)

# 6) Decision v2:
#    если ROI системно extreme, она не идёт в primary;
#    если extreme умеренно/редко — остаётся в primary с QC-флагом.
if roi in [133, 134, 167]:
    decision = "sensitivity_only"
elif roi == 160:
    decision = "qc_flag_keep"

Линейный тренд и detrended branch

Применялось к нашим рядам сейчас: QC — да; detrended branch — да в Stage 2.

Что помогает оценить: Проверяет медленный линейный дрейф и позволяет посмотреть, зависит ли метрика от удаления такого дрейфа.

\[x_t=\beta_0+\beta_1\tilde t+\varepsilon_t\]
\[x^{detrended}_t=x_t-(\hat\beta_0+\hat\beta_1\tilde t)\]

Полученные оценки

  • linear_trend_r2: median=2.77e-04; p95=0.0034; max=0.0341.
  • Для correlation_full baseline FDR=1041, detrended FDR=1042.
  • baseline_vs_detrended matrix_similarity≈1.

Интерпретация

Линейный тренд оказался не главным фактором: detrender почти не меняет full correlation. Главная нестабильность связана не с линейным drift, а с AR1.

Прокомментированный фрагмент алгоритма

# Линейный тренд: проверяем, растёт/падает ли сигнал во времени.
t = np.linspace(-1, 1, len(x))          # нормируем время для устойчивости
A = np.column_stack([np.ones_like(t), t])

# x ≈ beta0 + beta1 * t
beta, *_ = np.linalg.lstsq(A, x, rcond=None)
trend = A @ beta
resid = x - trend

# R² показывает, какую долю дисперсии объясняет линейный тренд.
ss_res = np.sum((x - trend) ** 2)
ss_tot = np.sum((x - x.mean()) ** 2)
trend_r2 = 1 - ss_res / ss_tot

# В detrended branch дальше используется resid вместо x.

Подводные камни

  • Детрендинг не удаляет нелинейные drift/shift.
  • Если temporal phenotype сам важен, агрессивный detrend может удалить часть сигнала.

ACF/PACF/AR1/AR2 и AR-residualization

Применялось к нашим рядам сейчас: диагностика — да; AR1 branch — да; AR2/AR(p) — пока не как full branch.

Что помогает оценить: Оценивает временную инерционность BOLD-ряда. Это критично, потому что автокорреляция может раздувать групповые различия в connectivity.

\[\rho(k)=\operatorname{corr}(x_t,x_{t-k})\]
\[x_t=\phi_1x_{t-1}+\cdots+\phi_px_{t-p}+\varepsilon_t\]

Полученные оценки

  • Медиана ACF lag1 = 0.441; p75 = 0.764; p95 = 0.9091.
  • Медиана PACF lag2 = 0.0672, хвосты: min=-0.6694, max=0.3797.
  • По AR1 diagnostic: 83/159 ROI имеют HC/SZ различия по AR1 p<0.05; обычно AR1_HC > AR1_SZ.
  • Для correlation_full AR1 убрал FDR-surviving edges: 1041 → 0, но оставил 859 near-miss p<0.05.

Интерпретация

AR1 оказался центральным методологическим фактором. Он не просто “чистит шум”: сам AR1 различается между группами. Поэтому AR1 одновременно preprocessing control и отдельный temporal phenotype.

Прокомментированный фрагмент алгоритма

# ACF lag k: насколько x[t] похож на x[t-k].
def acf(x, k):
    return corr(x[k:], x[:-k])

acf1 = acf(x, 1)
acf2 = acf(x, 2)

# PACF lag 2 — связь x[t] с x[t-2] после учёта x[t-1].
# Это помогает понять: достаточно AR1 или есть самостоятельная структура на lag 2.
pacf_values = pacf(x, nlags=max_lag)
pacf2 = pacf_values[2]

# AR(1): x[t] = phi * x[t-1] + eps[t]
y = x[1:]
Xlag = x[:-1]
phi = np.dot(Xlag, y) / np.dot(Xlag, Xlag)
resid = y - phi * Xlag

Прокомментированный фрагмент алгоритма

# Линейный тренд: проверяем, растёт/падает ли сигнал во времени.
t = np.linspace(-1, 1, len(x))          # нормируем время для устойчивости
A = np.column_stack([np.ones_like(t), t])

# x ≈ beta0 + beta1 * t
beta, *_ = np.linalg.lstsq(A, x, rcond=None)
trend = A @ beta
resid = x - trend

# R² показывает, какую долю дисперсии объясняет линейный тренд.
ss_res = np.sum((x - trend) ** 2)
ss_tot = np.sum((x - x.mean()) ** 2)
trend_r2 = 1 - ss_res / ss_tot

# В detrended branch дальше используется resid вместо x.

Подводные камни

Как делались статистические тесты перед таблицей метрик

Эта секция нужна, чтобы числа tests/FDR, baseline FDR, AR1 FDR, survived, near-miss, min AR1 q и shrinkage не выглядели как непонятные “служебные” колонки. Это не отдельные метрики мозга, а сводка статистической проверки каждой connectivity-метрики.

1. Что является одним статистическим тестом?

Один тест = одно ребро графа, то есть одна пара ROI, по которой мы сравниваем значения метрики между HC и SZ.

  • Для undirected-метрик ребро i—j считается один раз.
  • Для directed-метрик i→j и j→i считаются разными рёбрами.
  • Для bounded-запусков тестов меньше, потому что бралась ограниченная подвыборка ROI или пар.
\[ N_{undirected}=\frac{159\cdot 158}{2}=12561 \] \[ N_{directed}=159\cdot 158=25122 \]

2. Что именно сравнивали между группами?

Для каждого ребра у нас есть набор значений метрики по субъектам. Например, для ребра ROI 10 — ROI 20 есть 15 значений у HC и 24 значения у SZ.

Дальше эти два набора сравниваются непараметрическим тестом Mann–Whitney U.

\[ H_0: X_{HC}^{(i,j)} \text{ и } X_{SZ}^{(i,j)} \text{ взяты из одного распределения} \] \[ H_1: \text{распределения значений ребра в HC и SZ различаются} \]

Почему Mann–Whitney: выборка маленькая, распределения значений ребра не обязаны быть нормальными, а многие метрики ограничены диапазоном или имеют тяжёлые хвосты.

3. Что такое FDR и откуда берутся q-value?

Если тестов тысячи, обычное p < 0.05 даёт много случайных “значимых” рёбер. Поэтому p-value по всем рёбрам одной метрики и одной ветки preprocessing поправляются методом Benjamini–Hochberg FDR.

FDR контролирует ожидаемую долю ложных находок среди тех рёбер, которые мы объявили значимыми.

\[ q_{(i)} \approx p_{(i)}\frac{m}{i} \]

Здесь \(p_{(i)}\) — p-value после сортировки по возрастанию, \(m\) — число тестов, \(i\) — ранг p-value. В реальной реализации ещё применяется монотонная коррекция с хвоста, чтобы q-value не нарушали порядок.

4. Как читать колонки таблицы метрик

  • tests/FDR — сколько p-value вошло в одну FDR-поправку.
  • baseline FDR — сколько рёбер прошло \(q<0.05\) в baseline-ветке.
  • AR1 FDR — сколько рёбер прошло \(q<0.05\) после AR1-residualization.
  • survived — сколько baseline-FDR рёбер остались FDR-значимыми после AR1.
  • near-miss — сколько baseline-FDR рёбер после AR1 всё ещё имеют \(p<0.05\), но не обязательно \(q<0.05\).
  • min AR1 q — минимальное FDR-corrected q-value после AR1. Если оно около 0.05–0.10, это near-miss-зона, а не полная пустота.
  • shrinkage — насколько уменьшился групповой эффект после AR1.
\[ \Delta_{ij}^{branch}=\operatorname{median}\big(M_{SZ,ij}^{branch}\big)-\operatorname{median}\big(M_{HC,ij}^{branch}\big) \] \[ \operatorname{shrinkage}_{ij}=\frac{|\Delta_{ij}^{AR1}|}{|\Delta_{ij}^{baseline}|+\varepsilon} \]

Если shrinkage около 0.42, значит после AR1 осталось примерно 42% исходной baseline-разницы. Если shrinkage около 0.10 — AR1 почти полностью съел групповой эффект. Если shrinkage больше 1 — после AR1 эффект стал сильнее, это надо смотреть отдельно по ребру.

Главная интерпретация: AR1 FDR = 0 не равно “ничего нет”. Например, для correlation_full было 1041 → 0 FDR-рёбер, но при этом 859 near-miss рёбер с p_AR1 < 0.05, min AR1 q = 0.087, shrinkage ≈ 0.42. Это означает: эффект после AR1 ослаблен и не проходит множественную поправку, но nominal-сигнал не исчез полностью.

Прокомментированный псевдокод статистического слоя

# Для одного ребра i--j есть значения метрики по субъектам.

# 1) Непараметрическое сравнение групп.
# Mann–Whitney не требует нормальности распределения метрики.
stat, p_value = scipy.stats.mannwhitneyu(
    hc_values,
    sz_values,
    alternative="two-sided"
)

# 2) Эффект: медианная разница SZ-HC.

# 3) После того как p-value посчитаны для всех рёбер,

reject, q_values, _, _ = statsmodels.stats.multitest.multipletests(
    p_values,
    alpha=0.05,
    method="fdr_bh"
)

# 4) Summary по baseline и AR1:

AR1_FDR = np.sum(q_ar1 < 0.05)

correlation_full — Pearson full correlation

самописная реализация стандартной формулы Формула Pearson стандартная, но вычисление всей матрицы выполнено внутри проекта через нормировку и матричное произведение.

Какие cards: correlation_full   secondary_candidate

Тип реализации: самописная векторизованная реализация стандартной формулы Pearson. Код не вызывает “магическую” функцию для всей матрицы, а явно центрирует ряды, нормирует их и берёт матричное произведение.

Что измеряет: Линейная синхронность двух ROI на одном временном ряду. Выход — симметричная матрица ROI×ROI.

\[r_{ij}=\frac{\sum_t(x_{ti}-\bar x_i)(x_{tj}-\bar x_j)}{\sqrt{\sum_t(x_{ti}-\bar x_i)^2}\sqrt{\sum_t(x_{tj}-\bar x_j)^2}}\]

Алгоритм в коде — подробно и с комментариями

# X: time × ROI.
X = data.to_numpy(dtype=float)

# 1) центрируем каждый ROI-ряд
Xc = X - X.mean(axis=0, keepdims=True)

# 2) считаем норму каждого центрированного ROI-ряда
norm = np.sqrt((Xc ** 2).sum(axis=0, keepdims=True))
norm[norm < 1e-12] = 1.0

# 3) нормируем колонки: теперь длина каждого ROI-вектора = 1
Xn = Xc / norm

# 4) корреляционная матрица: скалярные произведения всех ROI-векторов
R = Xn.T @ Xn

# Выход: R[i,j] = Pearson correlation между ROI i и ROI j.
# Матрица симметричная; R[i,i] = 1.

Что получается на выходе

Матрица ROI×ROI или source×target. Далее для каждого ребра сравниваем HC vs SZ и получаем p/q/effect size.

Результаты текущих cards

  • baseline FDR=1041; AR1 FDR=0; near-miss=859; min AR1 q=0.0870.
  • Большой baseline SZ<HC pattern, но не primary evidence из-за AR1-FDR collapse.

correlation_kendall — Kendall tau-b

стандартная Используется Kendall tau-b через pandas/scipy, с поправкой на ties.

Какие cards: correlation_kendall   secondary_candidate

Тип реализации: стандартный метод tau-b. Используется pandas Kendall или scipy.stats.kendalltau(variant="b"), то есть версия с поправкой на равные значения/ties.

Что измеряет: Согласованность попарных порядков временных точек. Выход — симметричная матрица tau.

\[\tau_b=\frac{C-D}{\sqrt{(C+D+T_x)(C+D+T_y)}}\]

Алгоритм в коде — подробно и с комментариями

# Kendall tau-b не смотрит на величину значений напрямую.
# Он смотрит на пары временных точек.

# Пусть есть две временные точки a и b.
# Для ROI X: если X[a] < X[b], значит X "вырос" от a к b.
# Для ROI Y: если Y[a] < Y[b], значит Y тоже "вырос".
# Если оба ряда изменили порядок одинаково -> concordant pair.
# Если один вырос, а другой упал -> discordant pair.

from scipy.stats import kendalltau

tau, p = kendalltau(x, y, variant="b")

# tau-b поправляет знаменатель на ties — случаи, когда значения равны
# и порядок пары нельзя нормально определить.
# Выход: tau в [-1, 1].
# +1: все пары упорядочены одинаково; -1: все пары упорядочены противоположно.

Что получается на выходе

Матрица ROI×ROI или source×target. Далее для каждого ребра сравниваем HC vs SZ и получаем p/q/effect size.

Результаты текущих cards

  • bounded30: baseline FDR=246; AR1 FDR=64; survived=64.
  • Интересный кандидат, но надо расширить на full 159 ROI.

correlation_partial — partial correlation

самописная реализация стандартного precision-matrix подхода Код сам строит inverse/pseudo-inverse корреляционной матрицы.

Какие cards: correlation_partial   do_not_trust_yet

Тип реализации: самописная реализация стандартного precision-matrix подхода. Сначала строится корреляционная матрица всех ROI, затем pseudo-inverse, затем формула partial correlation.

Что измеряет: Связь двух ROI после линейного учёта остальных ROI. Выход — симметричная матрица partial correlations.

\[\rho_{ij\cdot rest}=-\frac{P_{ij}}{\sqrt{P_{ii}P_{jj}}},\quad P=R^{+}\]

Алгоритм в коде — подробно и с комментариями

# Partial correlation через precision matrix.
# Идея: берём корреляционную матрицу всех ROI и инвертируем её.

R = corr_matrix(X)              # ROI × ROI correlation matrix
P = np.linalg.pinv(R)           # precision matrix = pseudo-inverse

d = np.sqrt(np.abs(np.diag(P)))
partial = -P / np.outer(d, d)
np.fill_diagonal(partial, 1.0)

# Выход: partial[i,j] — линейная связь ROI i и j
# после учёта остальных ROI.
# Если full correlation была высокой, а partial≈0,
# значит связь могла идти через общие/третьи области.

Что получается на выходе

Матрица ROI×ROI или source×target. Далее для каждого ребра сравниваем HC vs SZ и получаем p/q/effect size.

correlation_directed — lagged directed correlation

самописная Lagged source→target matrix считается внутри проекта через past/future матрицы.

Какие cards: correlation_directed   secondary_candidate

Тип реализации: самописная векторизованная lagged-реализация. Строятся матрицы “прошлое” и “будущее”, затем одним матричным произведением считаются все source→target связи.

Что измеряет: Направленная лаговая ассоциация: строка=source, столбец=target. Не причинность.

\[M_{i\to j}(\ell)=r(x_i(t),x_j(t+\ell))\]

Алгоритм в коде — подробно и с комментариями

# Directed lagged correlation: M[src, tgt] = corr(src[t], tgt[t + lag])
lag = 1
past = X[:-lag]        # source values at time t
future = X[lag:]       # target values at time t+lag

# Центрируем и нормируем past/future отдельно.
past_c = past - past.mean(axis=0, keepdims=True)
fut_c = future - future.mean(axis=0, keepdims=True)

past_norm = past_c / np.sqrt((past_c ** 2).sum(axis=0, keepdims=True))
future_norm = fut_c / np.sqrt((fut_c ** 2).sum(axis=0, keepdims=True))

M = past_norm.T @ future_norm
np.fill_diagonal(M, 0.0)

# Что значит матричное произведение:
# M[i,j] = скалярное произведение нормированного ROI_i в прошлом
#          и нормированного ROI_j в будущем.
# Строка = источник, столбец = цель.
# Диагональ зануляется, чтобы не считать self-lag как межрегиональную связь.

Что получается на выходе

Выход — несимметричная матрица source×target: строка i означает “ROI i в момент t”, столбец j — “ROI j в момент t+lag”. Если M[i,j] велико, прошлое source i похоже на будущее target j. Это лаговая ассоциация, а не доказанная причинность.

Результаты текущих cards

  • full directed: tests=25 122; baseline FDR=3535; AR1 FDR=2951; survived=1760.
  • Самый живой текущий блок, но нужен lag scan.

Тип реализации: самописная KSG kNN реализация с scipy-примитивами. Используются cKDTree и digamma; это не histogram-binning MI.

Что измеряет: Нелинейная статистическая зависимость. CMI пытается контролировать Z.

\[I(X;Y)=\iint p(x,y)\log\frac{p(x,y)}{p(x)p(y)}dxdy\]

Алгоритм в коде — подробно и с комментариями

# KSG mutual information: оцениваем MI без явного разбиения значений на bins.
# Для каждой точки смотрим, насколько близко к ней лежат другие точки
# в совместном пространстве (X,Y).

from scipy.spatial import cKDTree
from scipy.special import digamma

xy = np.column_stack([x, y])
tree_xy = cKDTree(xy)

# 1) для каждой точки ищем расстояние eps до k-го соседа в joint-space.
# Chebyshev metric: расстояние = max(|dx|, |dy|).
dist, _ = tree_xy.query(xy, k=k+1, p=np.inf)
eps = dist[:, k]

# 2) считаем, сколько соседей попало в eps-окрестность отдельно по X и по Y.
tree_x = cKDTree(x.reshape(-1, 1))
tree_y = cKDTree(y.reshape(-1, 1))
nx = np.array([len(tree_x.query_ball_point([x[i]], eps[i]-1e-15, p=np.inf))-1 for i in range(n)])
ny = np.array([len(tree_y.query_ball_point([y[i]], eps[i]-1e-15, p=np.inf))-1 for i in range(n)])

# 3) KSG-формула через digamma.
mi = digamma(k) + digamma(n) - np.mean(digamma(nx+1) + digamma(ny+1))

# Смысл: если X и Y зависимы, в joint-space точки плотнее,
# чем ожидалось бы из отдельных распределений X и Y.

Что получается на выходе

Матрица ROI×ROI или source×target. Далее для каждого ребра сравниваем HC vs SZ и получаем p/q/effect size.

Что здесь делает KSG kNN: это не “просто histogram MI”. Для каждой временной точки алгоритм смотрит расстояние до k-го соседа в совместном пространстве \((X,Y)\). Потом он считает, сколько соседей попадает в такой же радиус отдельно по X и отдельно по Y. Если X и Y независимы, эти количества ведут себя одним образом; если зависимы — другим. Формула через digamma переводит эти counts в оценку mutual information. Для CMI идея та же, но учитывается ещё пространство Z: мы спрашиваем, остаётся ли связь X—Y после учёта Z.
Что означает KSG простыми словами: мы не делим значения на грубые bins. Вместо этого для каждой временной точки смотрим, сколько соседних точек находится рядом с ней в пространстве X, в пространстве Y и в совместном пространстве (X,Y). Если X и Y зависимы, то точки в joint-space “сжимаются” иначе, чем в отдельных пространствах. Формула через digamma переводит эти counts в оценку mutual information.

distance correlation

гибридная Используется пакет dcor, если доступен; иначе fallback внутри проекта.

Какие cards: dcor_full / dcor_directed / dcor_partial   mixed

Тип реализации: гибрид. Если установлен пакет dcor — используется он; иначе включается самописный fallback через попарные расстояния и double-centering.

Что измеряет: Зависимость через попарные расстояния. Может ловить нелинейность.

\[dCor(X,Y)=\sqrt{\frac{dCov^2(X,Y)}{\sqrt{dVar(X)dVar(Y)}}}\]

Алгоритм в коде — подробно и с комментариями

# Distance correlation: строим матрицы попарных расстояний во времени.
A = np.abs(x[:, None] - x[None, :])
B = np.abs(y[:, None] - y[None, :])

# Double-centering: убираем средние по строкам, столбцам и общее среднее.
A_centered = A - A.mean(axis=1, keepdims=True) - A.mean(axis=0, keepdims=True) + A.mean()
B_centered = B - B.mean(axis=1, keepdims=True) - B.mean(axis=0, keepdims=True) + B.mean()

dcov2 = np.mean(A_centered * B_centered)
dvar_x = np.mean(A_centered * A_centered)
dvar_y = np.mean(B_centered * B_centered)

dcor = np.sqrt(max(0, dcov2) / np.sqrt(dvar_x * dvar_y))

# Выход в [0,1]. Если dcor≈0, зависимости между рядами почти не видно.
# Плюс: ловит нелинейные зависимости. Минус: O(T²) на пару рядов.

AH / Arnhold-H

самописная Реализация через embedding и nearest neighbors.

Какие cards: ah_directed / ah_full / ah_partial   do_not_trust_yet

Тип реализации: самописная nearest-neighbor embedding реализация. Ряд переводится в фазовое пространство, затем сравниваются соседства source и target.

Что измеряет: Embedding nearest-neighbor directed dependence.

\[H_{X\to Y}\sim \frac{\text{distance in target for source-neighbors}}{\text{typical target-neighbor distance}}\]

Алгоритм в коде — подробно и с комментариями

# AH / Arnhold-H: embedding nearest-neighbor method.
# Сначала ряд превращается в точки фазового пространства.

def embed(x, m=3, tau=1):
    return np.column_stack([x[i: i + len(x) - (m-1)*tau] for i in range(0, m*tau, tau)])

Xs = embed(source)
Yt = embed(target)

# Для каждой точки source ищем ближайшего соседа в source-space.
source_tree = cKDTree(Xs)
_, nn_idx = source_tree.query(Xs, k=2)
source_neighbor = nn_idx[:, 1]

# Потом смотрим: соответствующие точки target тоже близки или нет?
dist_target_by_source_neighbor = norm(Yt - Yt[source_neighbor], axis=1)

# Нормируем на типичное ближайшее расстояние в target-space.
target_tree = cKDTree(Yt)
target_nn_dist, _ = target_tree.query(Yt, k=2)
ratio = dist_target_by_source_neighbor / target_nn_dist[:, 1]
value = min(1.0, 1.0 / mean(ratio))

# Если близость в source сохраняется в target, directed dependence выше.

# Ordinal pattern: заменяем значения в окне их порядком.

# потому что 1.2 < 3.1 < 5.0.

def ordinal_patterns(x, order=3, delay=1):
    patterns = []
    for t in range(len(x) - (order-1)*delay):
        window = x[t : t + order*delay : delay]
        patterns.append(tuple(np.argsort(window)))
    return patterns

4. FDR, p-value и почему “0” не равно “ничего”

Мы тестируем тысячи рёбер. Если оставить обычное p<0.05, случайные находки неизбежны. Поэтому используется Benjamini–Hochberg FDR: он контролирует ожидаемую долю ложных находок среди объявленных значимыми.

\[p_{(1)}\le\cdots\le p_{(m)},\quad q_{(i)}=\min_{j\ge i}\frac{m}{j}p_{(j)}\]
Пример correlation_full: baseline FDR=1041, AR1 FDR=0, но AR1 p<0.05 edges=2431, minimum AR1 p=2.063e-05, minimum AR1 q=0.08696. Значит, сигнал есть на nominal уровне, но при текущей множественной поправке не проходит q<0.05.

correlation_full — Pearson / full correlation

ненаправленная, симметричная, fullсамописная реализация стандартной формулы

Кратко: Измеряет линейную синхронность двух ROI: идут ли отклонения от среднего вместе или в разные стороны.

Базовая формула:
r_ij = Σ_t (x_i(t)-mean_i)(x_j(t)-mean_j) / sqrt(Σ_t (x_i(t)-mean_i)^2 Σ_t (x_j(t)-mean_j)^2)
Подробный алгоритм:
  1. Приводим таблицу к матрице time × ROI.
  2. Для каждого ROI вычитаем среднее.
  3. Делим каждый ROI на норму, чтобы масштаб не влиял на корреляцию.
  4. Считаем X_norm.T @ X_norm.
  5. Получаем симметричную ROI × ROI матрицу.

Что на выходе: Матрица [-1,1]; знак показывает вместе/противоположно.

Особенности: Сильно чувствительна к трендам, AR1, GSR и выбросам; у нас baseline есть, AR1-FDR нет.

Результат: tests/FDR=12561; baseline FDR=1041; AR1 FDR=0; survived=0; near-miss=859; min AR1 q=0.0870; shrinkage=0.4203; статус=secondary_candidate.
Код / псевдокод с комментариями

# Центрируем ROI: убираем средний уровень.
Xc = X - X.mean(axis=0, keepdims=True)
# Нормируем столбцы на длину; теперь скалярное произведение = Pearson r.
Xn = Xc / np.sqrt((Xc ** 2).sum(axis=0, keepdims=True))
R = Xn.T @ Xn  # ROI × ROI

самописная реализация ненаправленная нелинейная зависимость без знака

Простыми словами

Метрика спрашивает: если я знаю временной ряд ROI X, становится ли мне легче предсказать/описать значения ROI Y? Она ловит не только прямую линию, как корреляция, а любую статистическую зависимость — но не говорит, положительная она или отрицательная.

Формула

\[I(X;Y)=\int p(x,y)\log\frac{p(x,y)}{p(x)p(y)}\,dx\,dy\]

NewEDS использует не гистограмму, а KSG-like kNN-оценку:

\[\hat I(X;Y)=\psi(n)+\psi(k)-\frac1n\sum_{i=1}^{n}\left[\psi(n_x(i)+1)+\psi(n_y(i)+1)\right]\]
ОбозначениеСмысл в коде
nчисло валидных временных точек для пары ROI
kномер соседа, DEFAULT_K_MI
ε_iрасстояние от точки (x_i,y_i) до k-го соседа в joint-пространстве
n_x(i), n_y(i)сколько соседей попало в ε-окрестность в проекциях X и Y
ψdigamma-функция из scipy.special

Алгоритм NewEDS подробно

  1. Берётся пара ROI i,j. Из матрицы time × ROI вытаскиваются два вектора x и y.
  2. Строится маска валидных точек: точка используется только если и x[t], и y[t] конечны.
  3. Если валидных точек меньше или равно k, пара пропускается и возвращает NaN.
  4. Строится joint-пространство xy = column_stack([x, y]): каждая временная точка стала точкой на плоскости X–Y.
  5. Через cKDTree(xy) для каждой точки ищется расстояние до k-го ближайшего соседа. Саму точку тоже находят, поэтому запрашивается k+1 сосед.
  6. Радиус eps чуть уменьшается через np.nextafter(..., 0.0), чтобы не считать пограничного k-го соседа в проекциях лишний раз.
  7. Отдельно строятся деревья tree_x и tree_y.
  8. Для каждой точки считается, сколько соседей лежит в таком же радиусе eps[i] в одномерной проекции X и в одномерной проекции Y. Это nx и ny.
  9. В формулу через digamma подставляются n, k, nx, ny.
  10. Если оценка получилась отрицательной из-за численного шума, код обрезает её к нулю: max(0.0, mi).
  11. Результат записывается симметрично: MI[i,j] = MI[j,i]. Диагональ равна нулю.

Кодовая форма NewEDS с комментариями

def _knn_mutual_info(x, y, k=DEFAULT_K_MI):
    # 1. Приводим оба ROI-ряда к 1D float-векторам.
    x = np.asarray(x, dtype=np.float64).ravel()
    y = np.asarray(y, dtype=np.float64).ravel()
    n = int(min(x.size, y.size))

    # 2. KSG нельзя считать на слишком коротком ряду.
    if n <= k or n <= 3:
        return np.nan

    # 3. Совместное пространство: каждая точка = (x[t], y[t]).
    xy = np.c_[x[:n], y[:n]]

    # 4. Ищем k-го соседа в joint-пространстве по Chebyshev distance.
    tree_xy = cKDTree(xy)
    distances, _ = tree_xy.query(xy, k=int(k) + 1, p=np.inf)

    # 5. eps[i] = радиус до k-го соседа, чуть уменьшенный внутрь.
    eps = np.nextafter(distances[:, int(k)], 0.0)

    # 6. Строим деревья в одномерных проекциях X и Y.
    tree_x = cKDTree(x.reshape(-1, 1))
    tree_y = cKDTree(y.reshape(-1, 1))

    # 7. Считаем, сколько точек попало в eps-окрестность по X и по Y.
    nx = _neighbor_counts_with_fallback(tree_x, x.reshape(-1, 1), eps)
    ny = _neighbor_counts_with_fallback(tree_y, y.reshape(-1, 1), eps)

    # 8. KSG-like формула через digamma.
    mi = digamma(n) + digamma(int(k))          - np.mean(digamma(nx + 1.0) + digamma(ny + 1.0))

    # 9. MI теоретически неотрицательна; отрицательный хвост — численный шум.
    return float(max(0.0, mi)) if np.isfinite(mi) else np.nan

самописная реализация ненаправленная частичная / условная нелинейная

Простыми словами

Это вопрос: “X и Y связаны сами по себе или только потому, что оба зависят от Z?” В обычной MI общий драйвер может создать ложную связь X–Y. Conditional MI пытается вычесть объяснение через Z.

Формула

\[I(X;Y\mid Z)=\int p(x,y,z)\log\frac{p(x,y\mid z)}{p(x\mid z)p(y\mid z)}\,dx\,dy\,dz\]

В коде kNN-оценка реализована как:

\[\widehat I(X;Y\mid Z)=\psi(k)-\frac1n\sum_i\left[\psi(n_{xz}(i)+1)+\psi(n_{yz}(i)+1)-\psi(n_z(i)+1)\right]\]

Алгоритм NewEDS подробно

  1. Если в вызов пришёл control_matrix, NewEDS сначала линейно резидуализует все ROI по этим controls, а потом считает обычную mutinf_full на остатках. Это residual fallback.
  2. Если control_matrix нет, для каждой пары X,Y выбирается Z: либо явно заданный список control, либо все остальные ROI кроме X и Y.
  3. Из таблицы берутся колонки [X, Y] + Z и удаляются строки с NaN.
  4. Если control-колонок нет, код откатывается к обычной MI.
  5. Если controls есть, строятся пространства XZ, YZ, Z, XYZ.
  6. В XYZ через cKDTree находится расстояние до k-го соседа.
  7. В том же радиусе eps считаются количества соседей в пространствах XZ, YZ и Z: nxz, nyz, nz.
  8. Эти counts подставляются в CMI-формулу через digamma.
  9. Отрицательные оценки обрезаются к нулю.
  10. Результат симметрично пишется в матрицу [i,j] и [j,i].

Почему это опасно на fMRI

Если Z = все остальные ROI, размерность Z становится большой. KNN в высокой размерности быстро деградирует: соседей становится мало, расстояния становятся похожими, оценка шумит. Поэтому CMI теоретически красива, но на 600 time points и десятках/сотнях ROI очень хрупкая.

def _knn_conditional_mutual_info(x, y, z, k=DEFAULT_K_MI):
    # 1. X и Y — 1D ряды, Z — матрица controls: time × n_controls.
    x = np.asarray(x, dtype=np.float64).ravel()
    y = np.asarray(y, dtype=np.float64).ravel()
    z = np.asarray(z, dtype=np.float64)
    if z.ndim == 1:
        z = z.reshape(-1, 1)

    # 2. Выравниваем длины.
    n = int(min(x.size, y.size, z.shape[0]))
    if n <= k or n <= 3:
        return np.nan

    # 3. Строим пространства для условной MI.
    xz = np.c_[x[:n], z[:n, :]]
    yz = np.c_[y[:n], z[:n, :]]
    xyz = np.c_[x[:n], y[:n], z[:n, :]]

    # 4. Радиус eps берём из полного пространства XYZ.
    tree_xyz = cKDTree(xyz)
    distances, _ = tree_xyz.query(xyz, k=int(k) + 1, p=np.inf)
    eps = np.nextafter(distances[:, int(k)], 0.0)

    # 5. Считаем соседей в подпространствах.
    nxz = _neighbor_counts_with_fallback(cKDTree(xz), xz, eps)
    nyz = _neighbor_counts_with_fallback(cKDTree(yz), yz, eps)
    nz  = _neighbor_counts_with_fallback(cKDTree(z[:n, :]), z[:n, :], eps)

    # 6. Frenzel–Pompe-like CMI formula.
    cmi = digamma(int(k)) - np.mean(
        digamma(nxz + 1.0) + digamma(nyz + 1.0) - digamma(nz + 1.0)
    )
    return float(max(0.0, cmi)) if np.isfinite(cmi) else np.nan

Где в NewEDS: neweds/metrics/causal.py; функции: granger_matrix.

библиотечный statsmodels направленная p-value based линейная предсказательность

Простыми словами

Проверяет: если мы уже знаем прошлое target, помогает ли прошлое source лучше предсказывать будущее target? Если помогает — source “Granger-causes” target в статистическом смысле.

Формулы

\[\text{restricted:}\quad y_t=a_0+\sum_{r=1}^{p}a_r y_{t-r}+\varepsilon_t\]
\[\text{full:}\quad y_t=a_0+\sum_{r=1}^{p}a_r y_{t-r}+\sum_{r=1}^{p}b_r x_{t-r}+\varepsilon_t\]
\[H_0:\ b_1=b_2=\ldots=b_p=0\]

Алгоритм NewEDS подробно

  1. Для каждой направленной пары source → target берутся два ряда.
  2. Оставляются только временные точки, где оба ряда конечны.
  3. Проверяется минимальная длина: min_obs = lag * 2 + 5. Если данных мало, пара пропускается.
  4. Создаётся pair_df с колонками в порядке [target, source]. Это важно для statsmodels.grangercausalitytests.
  5. Вызывается grangercausalitytests(pair_df, maxlag=lag).
  6. Для каждого лага от 1 до lag достаётся p-value из ssr_ftest.
  7. Если лагов несколько, берётся минимальный p-value и умножается на число лагов: p_corr = min(1, p_min * n_lags). Это простая поправка за выбор лучшего лага.
  8. В матрицу записывается p-value, а не сила эффекта. Поэтому меньше = сильнее evidence против H0.

Кодовая форма NewEDS с комментариями

def granger_matrix(df, lag=DEFAULT_MAX_LAG, pairs=None):
    # Матрица p-values source→target.
    out = _init_matrix(n_cols, np.nan, diag=0.0)
    effective = _get_effective_pairs(n_cols, pairs, directed=True)

    for src, tgt in effective:
        # 1. Берём только валидные точки source и target.
        mask = finite[:, src] & finite[:, tgt]
        if mask.sum() <= lag * 2 + 5:
            out[src, tgt] = np.nan
            continue

        # 2. statsmodels ожидает target первым, source вторым.
        pair_df = pd.DataFrame({
            target_name: X[mask, tgt],
            source_name: X[mask, src],
        })

        # 3. Стандартный тест Грейнджера.
        tests = grangercausalitytests(pair_df, maxlag=int(lag), verbose=False)

        # 4. Берём p-value F-теста по каждому лагу.
        p_values = [tests[L][0]['ssr_ftest'][1] for L in range(1, lag + 1)]

        # 5. Если проверяли несколько лагов — простая коррекция за min-p.
        out[src, tgt] = min(1.0, min(p_values) * len(p_values))

    return out

Что на выходе

Направленная матрица p-values. Это не “чем больше, тем сильнее”, а наоборот: маленькое p-value означает, что source past даёт статистически значимое улучшение прогноза target.

гибридная реализация направленная частичная / control-sensitive p-value based

Простыми словами

Это попытка спросить: source помогает предсказывать target не просто сам по себе, а после учёта других рядов/controls. Но в больших ROI-наборах полный VAR становится тяжёлым и плохо обусловленным.

Как именно ветвится код

  1. Если передан control_matrix, NewEDS сначала резидуализует все ряды по controls, а потом вызывает обычный granger_matrix.
  2. Если controls нет и число ROI слишком большое: n_cols > 50, код логирует предупреждение и делает fallback на pairwise Granger. Это важно для 159 ROI.
  3. Если ROI мало (n_cols <= 40) и строк достаточно, код пытается fit совместной VAR-модели по всем рядам и вызывает test_causality.
  4. Если совместная VAR не подходит, для каждой пары собирается подтаблица [target, source] + control_cols и fit VAR на этом наборе.
  5. Результатом снова является p-value для source → target.

def granger_matrix_partial(df, lag, control=None, control_matrix=None):
    # Ветка 1: явные controls как матрица.
    if control_matrix is not None:
        residualized, _ = _residualize_df(df, control=control, control_matrix=control_matrix)
        return granger_matrix(residualized, lag=lag)

    # Ветка 2: полный VAR невозможен для больших N без регуляризации.
    if n_cols > 50 and control is None:
        # Для 159 ROI сюда и попадает полный набор.
        return granger_matrix(df, lag=lag)

    # Ветка 3: если ROI мало, пытаемся совместный VAR.
    if control is None and n_cols <= 40:

                caused=target_name,
                causing=[source_name],
                kind='f'
            ).pvalue
        return out

    # Ветка 4: pairwise VAR с controls.
    for src, tgt in directed_pairs:
        sub = df[[target, source] + control_cols].dropna()
        result = VAR(sub).fit(maxlags=lag, ic=None, trend='c')
        out[src, tgt] = result.test_causality(caused=target, causing=[source], kind='f').pvalue

te_full — гибрид: PyInform или самописная discrete Transfer Entropy

Где в NewEDS: neweds/metrics/causal.py; функции: compute_te_jitter, _transfer_entropy_discrete, transfer_entropy_matrix.

гибридная реализация направленная нелинейная дискретизация

Простыми словами

Transfer entropy спрашивает: даёт ли прошлое source дополнительную информацию о будущем target, сверх того, что уже известно из прошлого target?

Формула

\[TE_{Y\to X}=\sum p(x_t,x_{t-k:t-1},y_{t-k:t-1})\log_2\frac{p(x_t\mid x_{past},y_{past})}{p(x_t\mid x_{past})}\]

Алгоритм NewEDS подробно

  1. Для пары source → target выбираются валидные точки.
  2. Каждый ряд z-нормируется: вычитается среднее и делится на стандартное отклонение. Если std плохой, только центрируется.
  3. Если в ряду слишком много одинаковых значений, добавляется микроскопический jitter масштаба std × 1e-10. Это нужно, чтобы квантильная дискретизация не развалилась на ties.
  4. Ряд дискретизуется по квантилям на bins состояний. То есть непрерывный BOLD-сигнал превращается в последовательность целых состояний 0,1,2,...
  5. Если установлен pyinform, вызывается pyinform.transfer_entropy(source_discrete, target_discrete, k=lag).
  6. Если pyinform недоступен, NewEDS считает TE сам через частоты состояний.
  7. Для каждого времени t собираются: x_t = target future, x_past = target past, y_past = source past.
  8. Код считает частоты троек (x_t, x_past, y_past), пар (x_t, x_past), пар (x_past, y_past) и x_past.
  9. Через эти частоты оцениваются условные вероятности p(x_t | x_past, y_past) и p(x_t | x_past).
  10. Их отношение логарифмируется и усредняется с весом p_xyz.
  11. Записывается directed matrix element out[source, target].

Кодовая форма NewEDS с комментариями

def compute_te_jitter(source, target, lag=1, bins=DEFAULT_BINS):
    # 1. Нормируем каждый ряд: убираем масштаб.
    source_z = zscore_or_center(source)
    target_z = zscore_or_center(target)

    # 2. Если много ties, добавляем очень маленький шум.
    source_z = add_tiny_jitter_if_many_ties(source_z)
    target_z = add_tiny_jitter_if_many_ties(target_z)

    # 3. Квантильная дискретизация: continuous → integer states.
    source_d = discretize_quantile(source_z, bins)
    target_d = discretize_quantile(target_z, bins)

    # 4. Если есть PyInform, используем стандартную реализацию.
    if pyinform is not None:
        return pyinform.transfer_entropy(source_d, target_d, k=max(1, lag))

    # 5. Иначе самописный fallback по частотам.
    return _transfer_entropy_discrete(source_d, target_d, k=max(1, lag))


def _transfer_entropy_discrete(source_d, target_d, k=1):
    for t in range(k, n):
        x_t = target_d[t]             # будущее target
        x_past = target_d[t-k:t]      # прошлое target
        y_past = source_d[t-k:t]      # прошлое source

        # Счётчики нужны для условных вероятностей.
        count(x_t, x_past, y_past)
        count(x_t, x_past)
        count(x_past, y_past)
        count(x_past)

    # TE = средний log-ratio двух условных вероятностей.
    te += p_xyz * log2( p(x_t | x_past, y_past) / p(x_t | x_past) )

Что на выходе

Направленная матрица TE. Больше значение = source past сильнее добавляет информацию о target future. Не равно физиологической причинности.

te_partial — residualized Transfer Entropy wrapper

Где в NewEDS: neweds/metrics/causal.py; функции: transfer_entropy_matrix_partial, compute_te_jitter.

гибридная реализация направленная частичная через residualization

Простыми словами

Это не полноценная многомерная conditional TE по дискретным состояниям. В NewEDS partial TE сделана проще: сначала из source и target линейно вычитаются controls, а потом обычная TE считается на остатках.

Алгоритм NewEDS подробно

  1. Для пары source → target выбираются controls: либо control_matrix, либо явно заданный список, либо все остальные ROI.
  2. Строится линейная регрессия source на controls: source ~ 1 + controls.
  3. Берутся остатки source_res.
  4. То же делается для target: target_res.
  5. На остатках вызывается compute_te_jitter(source_res, target_res).
  6. Результат записывается в directed matrix.

Формула residualization

\[x^{res}=x-[\mathbf{1},Z]\hat\beta_x,\qquad y^{res}=y-[\mathbf{1},Z]\hat\beta_y\]

Кодовая форма NewEDS с комментариями

def residualize(y, x_ctrl):
    # Если controls нет, возвращаем исходный ряд.
    if x_ctrl is None or x_ctrl.size == 0:
        return y

    # Добавляем intercept: y ~ 1 + controls.
    x_aug = np.c_[np.ones(len(y)), x_ctrl]

    # OLS: beta = argmin ||y - X beta||².
    beta, *_ = np.linalg.lstsq(x_aug, y, rcond=None)

    # Остаток = то, что controls не объяснили.
    return y - x_aug @ beta

# Для каждой пары source→target:
src_res = residualize(src_vals, controls)
tgt_res = residualize(tgt_vals, controls)
te = compute_te_jitter(src_res, tgt_res, lag=lag, bins=bins)

Подводный камень

Это partial в смысле “линейно вычли controls перед TE”, а не строгая высокая-dimensional conditional TE с дискретным Z_past внутри формулы TE.

Результат

te_partial: baseline FDR = 1; AR1 FDR = 0; sensitivity-only.

ah_full — самописный Arnhold-H state-space interdependence

Где в NewEDS: neweds/metrics/information.py; функции: _H_ratio_direction, AH_matrix.

самописная реализация в коде directed=True state-space / embedding нелинейная геометрия

Важно про название. В registry у ah_full стоит directed=True. То есть несмотря на слово full, реализация возвращает направленную матрицу: AH[source,target] может отличаться от AH[target,source].

Простыми словами

AH не сравнивает значения точка-в-точку. Она сравнивает геометрию траекторий: если два момента времени похожи в динамике source, окажутся ли соответствующие моменты похожими в target?

Embedding

\[\mathbf{x}_t=(x_t,x_{t+\tau},x_{t+2\tau},\ldots,x_{t+(m-1)\tau})\]

То есть один временной ряд превращается в облако точек в m-мерном пространстве. Каждая точка — короткий фрагмент динамики.

Алгоритм NewEDS подробно

  1. Берутся source и target одинаковой длины.
  2. Задаются параметры embedding: embed_dim=m, tau.
  3. Для source строится source_embedding: строки вида [source[t], source[t+tau], ...].
  4. Для target строится target_embedding теми же индексами времени.
  5. Удаляются строки, где в source или target embedding есть NaN/Inf.
  6. В source-space строится cKDTree.
  7. Для каждой точки source ищется ближайший сосед в source. Запрашивается k=2, потому что первый сосед — сама точка, второй — реальный nearest neighbor.
  8. Берётся индекс этого source-соседа. Теперь смотрим: а где соответствующая точка с тем же индексом в target-space?
  9. Считается distance в target между текущей точкой и target-точкой, соответствующей source-соседу. Это “target distance induced by source neighbor”.
  10. Отдельно в target-space ищется настоящий ближайший сосед target-точки.
  11. Строится отношение: induced target distance / true target nearest distance.
  12. Если source-соседство хорошо согласовано с target-геометрией, отношение близко к 1.
  13. NewEDS усредняет ratio и возвращает min(1, 1/mean_ratio). Поэтому большее значение = более сильная согласованность.

Формула, соответствующая коду

\[R_{X\to Y}=\frac1N\sum_t \frac{\lVert \mathbf{y}_t-\mathbf{y}_{n_X(t)}\rVert}{\lVert \mathbf{y}_t-\mathbf{y}_{n_Y(t)}\rVert+\varepsilon},\qquad AH_{X\to Y}=\min\left(1,\frac1{R_{X\to Y}}\right)\]

Кодовая форма NewEDS с комментариями

def _H_ratio_direction(source, target, m=DEFAULT_EMBED_DIM, tau=DEFAULT_EMBED_TAU):
    # 1. Делаем delay embedding для source и target.
    embedded_len = len(source) - (m - 1) * tau
    source_embedding = np.empty((embedded_len, m))
    target_embedding = np.empty((embedded_len, m))

    for offset in range(m):
        start = offset * tau
        stop = start + embedded_len
        source_embedding[:, offset] = source[start:stop]
        target_embedding[:, offset] = target[start:stop]

    # 2. Убираем строки с NaN/Inf в любом embedding.
    valid = finite_rows(source_embedding) & finite_rows(target_embedding)
    source_valid = source_embedding[valid]
    target_valid = target_embedding[valid]

    # 3. В source-space ищем ближайшего соседа каждой точки.
    source_tree = cKDTree(source_valid)
    _, source_neighbor_idx = source_tree.query(source_valid, k=2)
    source_neighbor = source_neighbor_idx[:, 1]  # k=2: второй сосед, не сама точка

    # 4. Смотрим, насколько далеко соответствующие точки оказались в target-space.
    target_distance_by_source_neighbor = norm(
        target_valid - target_valid[source_neighbor], axis=1
    )

    # 5. Для нормировки ищем настоящий ближайший target-сосед.
    target_tree = cKDTree(target_valid)
    target_distances, _ = target_tree.query(target_valid, k=2)
    target_nearest_distance = replace_zeros(target_distances[:, 1], 1e-10)

    # 6. Ratio: если source-neighbor ведёт к почти ближайшему target-neighbor,
    # значит геометрия source хорошо согласована с геометрией target.
    ratios = target_distance_by_source_neighbor / target_nearest_distance
    return mean(finite(ratios))


def AH_matrix(data):
    ratio = _H_ratio_direction(source, target)
    value = min(1.0, 1.0 / ratio)
    out[source, target] = value

def compute_partial_AH_matrix(data, lag=1, control=None, control_matrix=None):

ordinal_full — самописная ordinal-pattern mutual information

Где в NewEDS: neweds/metrics/ordinal.py; функции: _ordinal_pattern, _ordinal_mi, ordinal_matrix.

самописная реализация ненаправленная ordinal patterns робастнее к амплитуде

Простыми словами

Метрика выбрасывает точные амплитуды и оставляет только форму коротких фрагментов: растёт-падает, максимум в середине, минимум в начале и т.д. Потом сравнивает, похожи ли такие локальные формы у двух ROI.

Формула

\[I(P_X;P_Y)=\sum_{a,b}p(a,b)\log_2\frac{p(a,b)}{p(a)p(b)}\]

Алгоритм NewEDS подробно

  1. Для каждого ряда берётся rolling window длины order с шагом delay. По умолчанию order=3, delay=1.
  2. Внутри окна берётся порядок значений, а не сами значения. Например, окно [10, 20, 15] кодируется как ранги [0, 2, 1].
  3. Если в окне есть NaN/Inf, код паттерна = -1.
  4. Паттерн превращается в целое число через base-order кодирование.
  5. Для пары ROI строятся две последовательности паттернов.
  6. Последовательности выравниваются по минимальной длине.
  7. Невалидные паттерны -1 выбрасываются.
  8. Если валидных паттернов меньше 20, возвращается NaN/0.
  9. Считаются частоты паттернов X, паттернов Y и совместных пар паттернов.
  10. По частотам считается mutual information между ordinal pattern sequences.

Кодовая форма NewEDS

def _ordinal_pattern(x, order=3, delay=1):
    # idx = [0, delay, 2*delay, ...]
    idx = np.arange(order) * delay
    patterns = []

    for t in range(n - idx[-1]):
        w = x[t + idx]  # короткое окно ряда
        if not np.all(np.isfinite(w)):
            patterns.append(-1)
            continue

        # Два argsort дают ранги значений внутри окна.
        # mergesort стабильный: ties обрабатываются детерминированно.
        rank = np.argsort(np.argsort(w, kind='mergesort'), kind='mergesort')

        # Превращаем ранговый паттерн в одно целое число.
        code = 0
        for r in rank:
            code = code * order + int(r)
        patterns.append(code)

    return np.array(patterns, dtype=int)


def _ordinal_mi(x, y):
    px = _ordinal_pattern(x)
    py = _ordinal_pattern(y)
    # Считаем MI между кодами паттернов.
    for (a, b), nab in joint_counts.items():
        mi += p_ab * log2(p_ab / (p_a * p_b))

Симметричная матрица ordinal MI. Большое значение = локальные формы сигналов синхронно меняются.

ordinal_directed — lagged ordinal-pattern MI

Где в NewEDS: neweds/metrics/ordinal.py; функции: ordinal_matrix_directed, _ordinal_mi.

самописная реализация направленная lagged ordinal patterns

Простыми словами

Это ordinal_full, но target сдвигается вперёд. Вопрос: похожи ли локальные формы source сейчас на локальные формы target позже?

Алгоритм NewEDS

  1. Задаётся lag=max(1, lag).
  2. Для пары i → j source = X[:, i].
  3. Target сдвигается: y_shifted = np.roll(X[:, j], -lag).
  4. Последние lag точек target ставятся NaN, чтобы не было wrap-around.
  5. Оставляются точки, где source и shifted target конечны.
  6. Считается _ordinal_mi(source, shifted_target).
  7. Результат пишется в out[i,j]. Обратное направление считается отдельно.

Кодовая форма NewEDS

def ordinal_matrix_directed(data, lag=1, order=3, delay=1):
    lag = int(max(1, lag))
    for i, j in directed_pairs:
        x = X[:, i]

        # target future: значение ROI j через lag шагов.
        y_shifted = np.roll(X[:, j], -lag)

        # Убираем wrap-around, чтобы конец ряда не стал началом.
        y_shifted[-lag:] = np.nan

        # Считаем ordinal MI между source now и target future.
        mask = np.isfinite(x) & np.isfinite(y_shifted)
        out[i, j] = _ordinal_mi(x[mask], y_shifted[mask], order=order, delay=delay)

FDR / q-values — самописная Benjamini–Hochberg correction

Где в NewEDS: neweds/core/group_pipeline.py и neweds/core/statistics.py; функции: _fdr_bh, fdr_bh, apply_pvalue_correction_matrix.

самописная реализация стандартной процедуры множественные сравнения

Простыми словами

Мы проверяем тысячи рёбер. Если использовать обычный p<0.05, часть “значимых” рёбер появится случайно. FDR переводит p-values в q-values так, чтобы контролировать ожидаемую долю ложных находок среди объявленных значимыми.

Формула BH

\[q_{(i)}=\min_{j\ge i}\left(\frac{m}{j}p_{(j)}\right)\]

Алгоритм NewEDS

  1. Берётся массив p-values по всем рёбрам данной метрики/ветки.
  2. p-values сортируются по возрастанию.
  3. Каждое p умножается на m / rank, где m — число тестов.
  4. С конца к началу применяется монотонная коррекция: q-values не должны убывать неправильным образом.
  5. q-values возвращаются в исходный порядок рёбер.
  6. Ребро считается FDR-significant, если q <= alpha, обычно 0.05.

Кодовая форма NewEDS

def _fdr_bh(p_values, alpha=0.05):
    n = len(p_values)

    # 1. Сортируем p-values.
    order = np.argsort(p_values)
    rank = np.arange(1, n + 1, dtype=np.float64)

    # 2. Raw BH adjustment: p * n / rank.
    p_adj = np.minimum(1.0, p_values[order] * n / rank)

    # 3. Монотонность: идём справа налево.
    for i in range(n - 2, -1, -1):
        if p_adj[i] > p_adj[i + 1]:
            p_adj[i] = p_adj[i + 1]

    # 4. Возвращаем q-values в исходный порядок.
    p_fdr = np.empty(n, dtype=np.float64)
    p_fdr[order] = p_adj

    # 5. significant = q <= alpha.
    return p_fdr, p_fdr <= alpha

Почему это важно для наших нулей

AR1 FDR = 0 не означает “нет вообще p<0.05”. Например, для correlation_full после AR1 было 859 near-miss рёбер с p<0.05, но min q = 0.087, поэтому FDR<0.05 не прошло.

Hurst / sample entropy diagnostics — реализованы, но в текущий Stage 1 fMRI CSV не вошли

Где в NewEDS: neweds/analysis/stats.py; функции: compute_hurst_rs, compute_hurst_dfa, compute_hurst_aggvar, compute_hurst_wavelet, compute_sample_entropy.

гибрид: nolds/hurst + самописные fallback-оценки одномерные time-series diagnostics

Что это оценивает

Hurst-оценки смотрят long-memory / persistence ряда. Sample entropy смотрит регулярность: насколько часто похожие фрагменты остаются похожими при увеличении длины шаблона.

Что реально сделано в коде

  1. compute_hurst_rs: сначала пробует пакет hurst.compute_Hc(..., kind='change'); если не получилось — fallback на nolds.hurst_rs.
  2. compute_hurst_dfa: вызывает nolds.dfa.
  3. compute_hurst_aggvar: самописно агрегирует ряд блоками размера m, считает дисперсию block means, затем slope в log-log.
  4. compute_hurst_wavelet: самописная PSD approximation: FFT → PSD → slope log(freq) vs log(PSD) → H.
  5. compute_sample_entropy: вызывает nolds.sampen, если ряд достаточно длинный и не константный.

Формулы

\[H_{aggvar}=1-\frac{slope}{2},\qquad slope=\mathrm{polyfit}(\log m,\log Var(\bar x_m))\]
\[H_{PSD}=\frac{1-slope}{2},\qquad slope=\mathrm{polyfit}(\log f,\log PSD(f))\]

Кодовая форма NewEDS

def compute_hurst_aggvar(series, max_n=100):
    arr = numeric_finite_1d(series)
    if len(arr) < 50:
        return np.nan

    variances, used_m = [], []
    for m in range(1, max_n + 1):
        # Делим ряд на блоки длины m.
        nb = len(arr) // m
        block_means = arr[:nb*m].reshape(nb, m).mean(axis=1)

        # Смотрим, как дисперсия средних меняется с размером блока.
        variance = np.var(block_means)
        if variance > 0:
            variances.append(variance)
            used_m.append(m)

    # H оценивается из log-log slope.
    slope, _ = np.polyfit(np.log10(used_m), np.log10(variances), 1)
    return 1.0 - slope / 2.0


def compute_sample_entropy(series):
    arr = numeric_finite_1d(series)
    if len(arr) < 20 or std(arr) < 1e-10:
        return np.nan
    return nolds.sampen(arr)

Источники алгоритмов: откуда взяты методы

Здесь разделено три уровня происхождения:

  • Математическая идея / статья — откуда взята сама метрика или классический алгоритм.
  • Библиотечная реализация — где используется стандартная функция Python-библиотеки.
  • Самописная адаптация NewEDS — где формула реализована вручную: построение матриц, перебор пар ROI, лаги, residualization, fallback, обрезка NaN/Inf.

Что именно в NewEDS самописное

Ниже — как это честно формулировать в отчёте:

  • Стандартная реализация: код напрямую вызывает библиотечный метод. Примеры: statsmodels.grangercausalitytests, scipy.signal.coherence, scipy.stats.kendalltau fallback.
  • Гибридная реализация: есть стандартный метод, но вокруг него написана наша логика: подготовка ROI-пар, лаги, controls, residualization, bounded screen, fallback. Примеры: granger_partial, te_full с PyInform/fallback.
  • Самописная реализация: сама численная процедура реализована в NewEDS по опубликованной формуле. Примеры: KSG MI/CMI, AH, ordinal MI, directed lagged matrix multiplication, fallback dCor.

Очень важная оговорка: если метрика помечена как «самописная», в тексте нужно писать не «мы изобрели метод», а «мы реализовали известный алгоритм/оцениватель по такой-то формуле, адаптировав его к матрицам ROI time series».
