# Спецификация работ по итогам методологического разговора

Дата фиксации: 23 июня 2026 года.

Эта спецификация переводит разговор в проверяемый план анализа. Главная
добавленная цель — проверить, насколько **каждая зарегистрированная метрика
NewEDS различает всех имеющихся субъектов SZ/ШЗ и HC/Н** в двух представлениях:

1. только серое вещество (`GM-only`);
2. весь мозг (`whole-brain`).

Это исследовательское сравнение методов, а не диагностическая или клиническая
валидация.

## 1. Зафиксированная когорта

- Всего субъектов: `39`.
- HC/Н: `15`.
- SZ/ШЗ: `24`.
- Пересечение субъектов в ROI- и tissue-наборах: `39/39`.
- Субъектов только в одном из двух наборов: `0`.

Каждый из 39 субъектов должен получить out-of-fold прогноз. Формулировка
«проверить всех субъектов» не означает обучить и проверить классификатор на тех
же данных: внешний цикл должен по очереди оставлять каждого субъекта вне
обучения.

## 2. Что именно сравнивается

### 2.1. Представление GM-only

В анализ входят только воксели `GM/data`. Их нельзя делить по порядку строк,
случайными блоками или прямоугольными пространственными кубами.

Для корректной connectivity-ветки нужны:

- координаты каждого GM-вокселя либо точное правило восстановления координат;
- GM-маска в исходном пространстве;
- атлас/парцеляционная маска и её версия;
- преобразование между пространством маски и пространством атласа;
- voxel-to-parcel таблица с контролем границ маски.

В текущих 39 HDF5 массивы `GM/xyz` отсутствуют. Поэтому полноценный GM-only
connectivity-анализ по всем метрикам пока **заблокирован пространственными
метаданными**. Подмена координат номером строки запрещена.

### 2.2. Представление whole-brain

Текущая практически доступная ветка — готовые AAL3 ROI-временные ряды.

Перед основным анализом необходимо разрешить несовпадение:

- исторический audit: `167 × 600`;
- текущие 39 CSV: `168 × 600`;
- исторический список atlas labels: `167`.

Нельзя молча удалить строку или присвоить ей метку. Должно быть получено
однозначное соответствие всех строк ROI названиям и сохранена таблица
`row_index -> atlas_label`.

### 2.3. Условие честного GM-only ↔ whole-brain сравнения

Предпочтительно использовать одинаковую парцеляцию и одинаковый порядок узлов.
Если GM-only и whole-brain будут построены на разных атласах или с разным числом
узлов, сравнивать классификационные показатели можно, но вывод должен называться
сравнением **полных представлений**, а не чистым эффектом исключения WM/CSF.

Конкатенация `GM + WM + CSF` является отдельной веткой
`all-tissues sensitivity` и не должна автоматически называться whole-brain
эквивалентом готовых AAL3 ROI.

## 3. Пространственная агрегация и однородность зон

Из разговора следуют обязательные ограничения:

- не использовать unconstrained cubic binning для извилистой коры;
- расширять пространственную область только через соседние валидные GM-воксели;
- прекращать рост области на нуле/границе маски;
- не считать atlas membership доказательством функциональной однородности;
- сохранять индивидуальность субъекта, а не только групповое среднее.

Для каждой зоны и каждого субъекта нужно оценить внутрозонную однородность:

- число вокселей;
- распределение попарных voxel-wise корреляций;
- медиану, IQR и устойчивые к выбросам квантили;
- долю положительных и отрицательных корреляций;
- долю вокселей, согласованных с представительным сигналом;
- пространственную связность выбранных вокселей;
- признак зоны, которой можно или нельзя доверять.

Зоны с плохой однородностью не удаляются задним числом по результату
классификации. Критерии допустимости задаются до использования меток HC/SZ.

## 4. Как получать один сигнал зоны

Нужно сравнить несколько способов, но не выбирать лучший по итоговой AUC:

1. обычное среднее;
2. первая главная компонента PCA;
3. ICA-компонента;
4. correlation-core — сигнал от связного ядра взаимно согласованных вокселей.

Выбор основного способа выполняется по label-blind критериям:

- внутрозонная согласованность;
- воспроизводимость во времени;
- устойчивость к удалению части вокселей;
- доля объяснённой дисперсии;
- число зон, проходящих заранее заданный QC.

### 4.1. Неоднозначность знака PCA/ICA

PCA и ICA определяют компоненту с точностью до знака. Без ориентации один и тот
же физиологический сигнал у разных субъектов может быть записан как `x(t)` или
`-x(t)`, что разрушит подписанные метрики и может создать ложный эффект
классификации.

Для каждого субъекта и каждой зоны необходимо:

- ориентировать компоненту так, чтобы корреляция с усреднённым
  стандартизованным сигналом зоны была неотрицательна;
- сохранить исходный знак, факт инверсии и значение корреляции;
- отдельно пометить случаи, где ориентация неопределима;
- провести sign-invariant sensitivity для метрик типа `r²`;
- не сравнивать неориентированные PCA/ICA с signed connectivity.

## 5. Временная структура и preprocessing

### 5.1. Тренд и стационарность

Для каждого регионального ряда до connectivity нужно сохранить:

- график или компактные trend diagnostics;
- линейный и, при необходимости, нелинейный detrending sensitivity;
- тесты стационарности с оговоркой об их мощности;
- долю и список рядов, не прошедших критерии;
- исходный ряд и преобразованный ряд.

Нельзя автоматически считать тренд артефактом: он может отражать движение,
дрейф прибора либо общую физиологическую динамику. Поэтому baseline и detrended
ветки должны сравниваться явно.

### 5.2. ACF, PACF и AR

До удаления авторегрессии нужно вычислить:

- ACF по лагам;
- PACF по тем же лагам;
- Ljung–Box summaries;
- распределения по субъектам и зонам;
- диагностические примеры минимум для 10 GM-рядов, упомянутые в разговоре.

Обязательные ветки:

- baseline без AR-удаления;
- AR(1)-residualized.

AR(2) добавляется как sensitivity только если после AR(1) остаётся
систематический PACF/остаточная автокорреляция. Порядок AR нельзя выбирать по
классификационной AUC.

После AR-удаления повторяются ACF, PACF и Ljung–Box. Ожидается не «идеальный
ноль», а документированное уменьшение предсказуемой временной структуры.

### 5.3. Частичная лаговая зависимость

Второй уровень проверки:

- частичная автокорреляция внутри каждого ряда;
- при наличии валидных узлов — частичная lagged correlation между рядами;
- lag × lag или lag × window исследования только после основного QC;
- полный lag × window × metric куб считать отложенной exploratory-веткой.

## 6. Глобальный сигнал

Глобальный сигнал не удаляется догматически. Для одной и той же конфигурации
строятся парные ветки:

- `without_GSR`;
- `with_GSR` либо global signal как явный control.

Нужно показать:

- изменение матриц и edge signs;
- долю наиболее чувствительных связей;
- изменение классификационных показателей;
- какие эффекты HC/SZ сохраняются в обеих ветках;
- различие whole-head global, GM-global и tissue nuisance signals.

## 8. Обязательная проверка различения HC/Н и SZ/ШЗ

### 8.1. Единица анализа

Единица анализа — субъект. Для каждой комбинации:

```text
representation × preprocessing × GSR mode × metric
```

получается одна feature matrix:

```text
39 subjects × metric-derived features
```

Для симметричных матриц используются элементы верхнего треугольника без
диагонали. Для направленных — все off-diagonal элементы с сохранением
направления.

### 8.2. Основной дизайн классификации

- Внешний цикл: LOOCV, 39 итераций.
- Каждый субъект получает ровно один out-of-fold прогноз.
- Внутренний цикл: стратифицированный CV только на 38 обучающих субъектах.
- Масштабирование, cross-subject imputation, feature selection и настройка
  модели выполняются только внутри train folds.
- Subject-local label-independent detrending/AR/GSR разрешены до CV, но их
  параметры и provenance сохраняются.
- Основная модель: L1-logistic regression.
- Контрольная модель: linear SVM.
- RBF-SVM — только sensitivity из-за малого `n`.
- Dummy/majority baseline обязателен.
- Ensemble нескольких метрик не входит в основной анализ; если он понадобится,
  выбор метрик должен быть вложен во внешний CV.

### 8.3. Показатели

Для каждой метрики и представления:

- ROC AUC;
- PR AUC;
- balanced accuracy;
- MCC;
- sensitivity;
- specificity;
- F1;
- confusion matrix;
- 95% CI;
- permutation p-value, где перестановка повторяет весь вложенный pipeline.

Минимум `1000` перестановок для основной таблицы и `2000` парных bootstrap
повторов для доверительных интервалов.

### 8.4. Множественные сравнения

Основная статистическая семья заранее фиксируется как:

```text
26 metrics × 2 representations × primary model
```

Permutation p-values корректируются Benjamini–Hochberg FDR. Preprocessing и GSR
sensitivity публикуются отдельными семьями, чтобы не смешивать основной вопрос
с разросшимся exploratory grid.

Нельзя:

- выбирать атлас по test AUC;
- выбирать preprocessing/GSR branch по held-out результату;
- выбирать лучшую модель на тех же OOF predictions и выдавать её оценку как
  несмещённую;
- удалять неудобных субъектов после просмотра их классификационной ошибки.

### 8.5. Парное GM-only ↔ whole-brain сравнение

Поскольку субъекты совпадают 39/39, для каждой метрики требуется:

- разность ROC AUC;
- разность balanced accuracy и MCC;
- paired bootstrap CI;
- paired permutation test;
- таблица субъектов, чья классификация изменилась;
- анализ устойчивости ранга метрик между двумя представлениями.

Если узлы или парцеляции различаются, это явно отражается как составная разница
представлений.

## 10. Что уже есть

- Совпадение когорты 39/39 подтверждено.

## 11. Что в существующем benchmark нужно исправить

Текущий `metric_benchmark.py` нельзя считать готовым финальным анализом:

- жёсткий список содержит не все 26 текущих метрик;
- отсутствуют wavelet и часть `ah_*`;
- `NaN/inf` сейчас молча заменяются нулями;
- метрики, отсутствующие хотя бы у одного субъекта, могут исчезнуть из общего
  списка без полноценной failure table;
- top-metric ensemble выбирается с риском circularity;
- bootstrap не является явно стратифицированным/парным;
- нет двух представлений GM-only и whole-brain;
- нет парного сравнения представлений;
- нет отдельной FDR-семьи по всем метрикам;
- нет полного subject-level OOF ledger.

Прототип следует переработать, а не запускать как есть.

## 12. Порядок выполнения

### P0 — разблокировать данные

1. Получить GM voxel coordinates или точное восстановление индексов.
2. Получить парцеляционную маску, версию и spatial transform.
3. Разрешить `168 ROI rows ↔ 167 labels`.
4. Уточнить физический TR, upstream detrending, motion correction и GSR.

### P1 — валидировать узлы и сигналы

1. Построить mask-constrained voxel-to-parcel mapping.
2. Посчитать внутрозонную однородность.
3. Сравнить mean/PCA/ICA/correlation-core label-blind способом.
4. Зафиксировать основной regional signal method.

### P2 — временной QC

1. Trend/stationarity.
2. ACF/PACF/Ljung–Box.
3. Baseline ↔ AR(1).
4. AR(2) только при остаточной структуре.
5. Without/with GSR.

### P3 — вычислить все метрики

1. Снимок registry.
2. Все 26 метрик для всех 39 субъектов.
3. Явная status/failure table.
4. Одинаковые параметры в сравниваемых ветках.

### P4 — классификационный benchmark

1. Nested LOOCV.
2. OOF prediction для каждого субъекта.
3. Permutation, CI и FDR.
4. Парное GM-only ↔ whole-brain сравнение.
5. Отчёт без диагностических заявлений.

### P5 — отложенные исследования

- lag × window × metric cube;
- partial lagged correlation между рядами;
- динамические subject-specific функциональные зоны;
- ensemble метрик.

Они выполняются только после валидной P4 и не должны задерживать основной
benchmark.

## 13. Критерий готовности

Работа считается завершённой, когда:

- все 39 субъектов присутствуют в итоговом OOF ledger;
- обе основные репрезентации имеют однозначное происхождение;
- все 26 метрик либо успешно рассчитаны, либо имеют явную причину отказа;
- ни один invalid result не заменён нулём;
- preprocessing и GSR не выбраны по test performance;
- есть FDR-corrected таблица различения HC/SZ;
- есть парная таблица GM-only ↔ whole-brain;
- код, параметры, среда, время и SHA-256 сохранены в `new_results`.
